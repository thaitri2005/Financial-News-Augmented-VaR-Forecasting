# M1-01 raw artifact commit contract

**State:** design contract to implement and verify before marking M1-01 done. **Inputs:** bounded synthetic payloads; no real source adapter or data refresh.

The storage root is explicitly configured and resolved. Its `.staging/` and `committed/` subdirectories must resolve inside that root. A source ID contains only lowercase ASCII letters, digits and underscores. A request identity contains bounded, nonsecret string/integer fields describing interval/page/cursor hash and adapter version. Never pass authorization headers or a live page token into a manifest.

`raw_id = SHA256(canonical JSON of source_id, SHA256(canonical request identity), payload SHA256)`; each component is preserved in the manifest. Canonical JSON is UTF-8, sorted keys, fixed separators, and no `NaN` or custom objects. The key is independent of attempt/retrieval time, making exact replays idempotent. A changed payload for an otherwise identical request gets a new raw ID/version. Repeated observations of an existing artifact require a later observation ledger; they never edit its first committed manifest.

Write a bounded payload and `manifest.json` to a unique directory under `.staging/`, flush and sync each file, then atomically rename the **complete directory** to `committed/<source_id>/<raw_id>/` on the same volume. Readers enumerate `committed/` only and validate the checksum/schema before consuming. This avoids an interval when only one of two files is public. The manifest state in a committed directory is `committed`; staging visibility itself supplies the interim state. An invalid/partial staging directory is never exposed. File-sync and atomic rename support restart after process interruption; abrupt power loss still requires on-disk checksum validation and is not claimed crash-proof.

Before a new write, verify any existing committed artifact. If a prior matching staging directory contains a complete valid manifest/payload, finish its rename. If staging is incomplete/corrupt, leave it identifiable for a later maintenance/quarantine task, create a new unique stage, and continue. A forced interruption before rename leaves a valid stage; after rename it leaves a valid commit. A replay either resumes or returns the exact committed artifact. Commit never overwrites a different artifact. Cursor advancement belongs to the future adapter and occurs **only after** this commit call succeeds; restarting the adapter may repeat a page safely.

The first API-page limit is 32 MiB; larger original archive files need a separate streamed source-file adapter. The caller supplies `row_count` and interval-completeness evidence; this storage layer validates nonnegative/type/identity/hash invariants, but does not claim that it parsed news rows or exhausted API pagination. No full Arrow/news schema is built before its consumer exists.

Tests exercise both interruption boundaries, an incomplete stage, replay, content corruption, distinct changed payloads, illegal IDs/secret-shaped request keys, and path escapes via symlinked storage subdirectories. Never clean or recursively move production raw data to satisfy a test.

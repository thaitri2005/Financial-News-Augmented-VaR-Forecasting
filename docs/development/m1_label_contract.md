# M1-04 adjacent-session label contract

One label belongs to an XNYS forecast origin `t`, with `target_start_session=t` and `target_end_session=next_session(t)`. Its value is decimal simple **price** return `C_next/C_t - 1`: a 1% rise is `0.01`, a 1% fall is `-0.01`. The observed label is separate from the feature row and is never available to a forecast issued at origin `t`. The source is FRED `SP500`; Cboe VIX never substitutes for either price. Scheduled cash close timestamps describe the holding period, not when FRED values were delivered.

Inputs are the frozen `CalendarSnapshot`, one audited `SP500` `MarketSource`, and an explicit UTC-aware map `price_available_at[session]`. The label availability timestamp is `max(available_at(C_t), available_at(C_next))`. A numeric price without defensible availability metadata is not a trainable label. A prospective map uses actual observed/release time; a historical proxy map may use the **next** exchange-session forecast cutoff as the declared prior-session availability assumption, because original FRED release vintages were not collected. Retrieval in 2026 is retained separately and is never backdated to an origin. The builder does not invent a cutoff for a session outside the saved origin grid; the calendar must be deliberately extended or another documented availability source supplied for edge labels.

Missing `C_t` or `C_next`, missing corresponding availability, nonpositive/nonfinite values, or a mismatch between source series and target role produce explicit skipped-origin reasons. No forward fill, row shift, nearest-date join or bridge across an intermediate exchange session is allowed. A missing close on session `s` affects labels starting at `s` and at `previous_session(s)`; a later pair of adjacent valid sessions can form its own label. Calendar origin and next-session keys, not source file position, define adjacency.

Each produced label records frozen target-source SHA/path/retrieval, target vintage identity, calendar/profile identity, target start/end sessions and scheduled close times, the two close levels, decimal simple return, later UTC availability, and availability basis. `market_manifest_id` remains null until M1-04B creates and validates the normalized market-observation manifest; a raw-source hash is not mislabeled as that future manifest. A label becomes eligible for a training refit only if its `label_available_at <= refit_cutoff`; equality is allowed. Before close `t`, `y_(t-1)` ends at today's unobserved close, so the newest normally eligible historical label under this assumption is `y_(t-2)`. A changed raw price snapshot, calendar, or availability policy produces a new derived label version and invalidates later models/reports that used the earlier mapping; it does not edit the old source.

M1-04 checks this contract with synthetic known-price and boundary fixtures, without exporting a final-period return distribution. M1-04B later writes the full normalized observation/label tables, after a fresh ≥3 GiB normalization preflight and explicit vintage policy. Notebook 04 will independently inspect temporal alignment before model use; a synthetic test does not close the market dataset gate.
